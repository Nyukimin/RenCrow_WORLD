# R05: independent WORLD foundation

Status: R05 source implementation and canonical three-OS source checks complete. Windows and macOS behavior, production integration, and runtime acceptance remain unverified. This is the WORLD-owned R05 contract. The cross-module v0.4 redesign under the workspace `tmp/` directory is a proposal; this document adopts only the R05 subset below.

## Ownership and boundary

WORLD owns WorldID-scoped state, logical SpatialBundle validation, and deterministic clock and visitor transitions. CORE retains Agent identity, Task, policy, conversation, and Memory. The R05 executable reads explicit local files, bootstraps one selected world, prints a bounded inspection result, and exits. It has no listener, persistent state, external provider, LLM, Task, or network call. R06 owns committed event/revision and persistence; R07 owns authenticated HTTP. The CORE/PORTAL R04 mock format is not a WORLD wire contract.

## R05 input contract

Both files are UTF-8 JSON, each at most 1 MiB. The decoder rejects duplicate object keys at every depth, unknown fields, trailing documents, unsupported versions, and malformed JSON. No input writes to the filesystem. The configuration path and WorldID are explicit command arguments. A relative `spatial_bundle_path` is resolved against the directory containing the configuration file, not the process working directory. The caller supplies an explicit RFC 3339 timestamp to the command; the executable never reads wall-clock time for bootstrap.

Configuration version 1 has exactly these fields:

```json
{
  "schema_version": 1,
  "worlds": [
    {
      "world_id": "rencrow-home",
      "spatial_bundle_path": "house-spatial.json",
      "time_zone": "Asia/Tokyo",
      "time_scale": 1
    }
  ]
}
```

`worlds` must contain 1–32 entries with unique WorldIDs. Each WorldID is a nonempty, valid UTF-8 opaque ID with no surrounding whitespace or control character. Every field is required. `spatial_bundle_path` is nonempty. `time_zone` must be `UTC` or a resolvable, named IANA zone under `Africa/`, `America/`, `Antarctica/`, `Arctic/`, `Asia/`, `Atlantic/`, `Australia/`, `Europe/`, `Indian/`, `Pacific/`, or `Etc/`. Local/implicit zones and host-only namespaces are rejected. `time_scale` is positive and finite. No server, storage, auth, or snapshot settings are accepted in version 1. The config is an input to an inspection command and is not installed into the runtime Workspace by this work package.

SpatialBundle version 1 has exactly `version`, `world_id`, `rooms`, `edges`, and `anchors`. `world_id` must match the selected configured world. `rooms`, `edges`, and `anchors` are required arrays, which may be empty. Each room has `id`; each edge has `id`, `from_room_id`, `to_room_id`; each anchor has `id`, `room_id`, `measurement_status`, and an explicit `position: null`. IDs are nonempty valid UTF-8 opaque values without surrounding whitespace or controls. IDs are unique within their respective entity type, and edges/anchors must reference existing rooms. For R05 file input, `measurement_status` must be `unverified`. Coordinates are unknown and must not be fabricated as zero vectors. Empty topology is a valid bootstrap input and gives no claim of logical or spatial readiness. Measured geometry requires a later contract for units, axes, and provenance. In-memory domain types may represent measured anchors but the R05 file boundary rejects them.

## Domain contract

Every operation is selected by an exact WorldID. Bootstrap creates exactly eight resident IDs: `mio`, `shiro`, `kuro`, `midori`, `aka`, `ao`, `kin`, and `gin`. `lumina` is a visitor, absent until an explicit valid Visit; unknown actors are rejected. Visit validity uses real UTC in the half-open interval `[valid_from_utc, valid_until_utc)`. An explicit departure requires the matching active Visit, and advancing to the interval end removes the visitor. Each operation returns a new state without mutating its input or another world.

World time is computed from an explicit UTC origin, a resolved time zone, and a positive scale. The clock rejects rollback. A different number of advance calls to the same final UTC time gives the same world time. Time inspection and pure transitions do not commit an event or increase revision; R05 revision is 0. `spatial_ready` remains false until real measured navigation, collision, and seating data pass a later gate.

Domain timestamps are concrete instants. Go's zero `time.Time` denotes `0001-01-01T00:00:00Z`, which is valid as a clock origin, observation, or Visit boundary; missing timestamp fields must be rejected at a serialized input boundary before conversion to these domain types. An empty or negative Visit interval remains invalid.

## Inspection and acceptance

The one-shot `rencrow-world inspect` command requires `--config`, `--world-id`, and `--at` (strict RFC 3339 Nano syntax with an explicit offset). It returns one newline-terminated JSON object with exactly `schema_version: 1`, `world_id`, `resident_actor_ids` (the eight sorted IDs), `visitor_present: false`, `world_time_utc`, `world_time_local`, `spatial_ready: false`, and `world_revision: 0`. Both output times must be representable as RFC 3339 Nano with years 0001–9999 and a whole-minute UTC offset; otherwise the command rejects the input before writing stdout. The command selects a WorldID from the configuration before reading its SpatialBundle. It must not emit raw geometry, secrets, or a production WorldSnapshot. Invalid input exits nonzero with a bounded error on stderr; stdout is reserved for a successful result.

R05 source acceptance requires strict configuration and SpatialBundle rejection cases, WorldID isolation, eight residents and visitor invariants, clock determinism, a valid executable inspection and invalid-input exit, Linux behavior tests, and native Go build/vet on Linux, Windows, and macOS. The WORLD-owned `scripts/test-local.plan.json` is the source-check plan; its `go test` step runs on Linux, following the repository-wide Test Execution Policy. A build alone does not establish behavior on another OS. Windows and macOS behavior, source, tests, commit, and cross-platform evidence are reported separately from production/runtime acceptance; three-OS behavior remains unverified until it is exercised under an agreed test route.
