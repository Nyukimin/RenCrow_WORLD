# R06: durable EventStore foundation

Status: R06 source implementation of the EventStore foundation. Linux and Windows behavior is verified by `go test ./...` (including real-process crash injection), macOS behavior is unverified, and CORE projections, production handlers, backup/restore operation, and live acceptance remain unimplemented or unverified. R07 adds an explicit-config HTTP source foundation; its route/port is not adopted. The W14 acceptance matrix entries stay `not_run`; this document records source-level coverage only.

## Scope

`internal/store` is a Go library with one logical writer over SQLite WAL. It is not a running service and has no listener, route, port, credential, LLM, Tool, or network call. R05 `rencrow-world inspect` remains unchanged and does not use the Store.

The Store owns:

- an authoritative Event log scoped by `world_id`, `timeline_id`, `timeline_epoch`;
- one immutable State projection per committed transaction, with a canonical SHA-256 hash;
- a Receipt per Command, including rejected Commands;
- resource capacity, consumption, and per-actor/per-activity reservations;
- Snapshot and per-transaction State deltas for deterministic replay.

Handlers are registered typed Go functions (`Store.Register`). They receive the current State and a JSON payload and return the next State, Events, and reservation changes. They never receive a clock, random source, network, LLM, or database handle. R06 ships no production handler set; R10/R11 own activity and spatial rules.

## Transaction commitment

`Append(Command)` opens one SQLite transaction and, in order:

1. resolves the idempotency namespace (`world_id + timeline_id + timeline_epoch + client_id + idempotency_key`) and compares the canonical body digest (SHA-256 over action, canonical payload, and `expected_state_seq`);
2. loads the timeline State at `state_seq`;
3. checks strict CAS when `expected_state_seq` is present;
4. runs the registered handler and applies reservations/consumption;
5. writes Events `state_seq+1 … state_seq+N` under one `txn_id`, updates State and its hash, writes reservation/resource rows, and writes the Receipt;
6. commits once.

A crash before commit rolls back all six steps. The Event log is authoritative; the State row is a projection. A committed Receipt names its `txn_id` and Event IDs. A rejected Receipt (CAS mismatch, resource conflict, reservation mismatch, invalid reservation, unknown action, handler error) has no `txn_id` or Event references and changes no State. Malformed commands, unknown action scope, and limit violations return a Go error and write no Receipt.

Limits: at most 128 Events and 256 KiB of serialized Event kind/payload per transaction; the input payload is also capped at 256 KiB. Event pages are capped at 500 Events and 2 MiB by default and never split a transaction; `Page` returns whole transactions and a cursor at the last returned transaction boundary.

Replay uses the latest Snapshot at or before the requested sequence plus the saved per-transaction State deltas. It never reruns a handler, LLM, Tool, or current rule, and it does not read wall-clock time, so the canonical hash is independent of when replay runs. A new `timeline_epoch` starts at `event_seq = 0` and is isolated from the old epoch.

## Schema

Tables (all scoped by the triple above):

| Table | Purpose |
|---|---|
| `timeline` | current `event_seq`, `state_seq`, canonical State JSON/hash |
| `snapshot` | initial/checkpoint State at a sequence |
| `txn` | transaction id, contiguous first/last sequence, receipt id, State delta, hash |
| `event` | ordered Events, kind, payload, explicit `recorded_at` |
| `receipt` | idempotency key/digest, committed/rejected status, txn/Event refs |
| `resource` | capacity and consumed quantity |
| `reservation` | resource, actor, activity, quantity |

SQLite is opened with WAL, `synchronous=FULL`, `busy_timeout`, foreign keys, and `_txlock=immediate`; the connection pool is limited to one connection so Commands serialize as a single logical writer. The driver is `modernc.org/sqlite` v1.60.1 (pure Go, no cgo), chosen so the same source builds on Linux, Windows, and macOS without a C toolchain. Linux and Windows have executed the store tests; macOS has not.

A live database file copy is not a backup. Snapshot/backup and restore-to-new-epoch APIs are not implemented in this unit; until they are, operational backups must stop the writer and copy the closed database plus WAL, or use a later owner-provided backup path.

## Evidence

| Test | Covers |
|---|---|
| `TestAtomicCommitAndReceipt` | 3 Events, one transaction, State/Receipt/Event sequence agreement |
| `TestIdempotentRetryReturnsSameReceipt` | same key/body returns the same Receipt and no second effect |
| `TestIdempotencyConflictOnDifferentBody` | same key/other body is rejected as a conflict |
| `TestStrictCAS` | stale `expected_state_seq` is `state_conflict`; new key/sequence succeeds |
| `TestReservationsAreAllOrNothing` | two concurrent starts for one chair and one drink: one commits, no partial reservation |
| `TestCancelReleasesAndCompleteConsumesOnce` | cancel releases, complete consumes exactly once |
| `TestPaginationKeepsTransactionsWhole` | pages never split a transaction; cursor follows the boundary |
| `TestCommandLimits` | 129 Events and 300 KiB payload are refused before commit |
| `TestReplayHashIsDeterministic` | replay hash equals live hash and is stable across replays |
| `TestRestoreStartsNewEpoch` | a new epoch starts at sequence 0 while the old epoch remains independent |
| `TestCrashRecovery` | process exit at `events`, `state`, `receipt`, and `commit`; reopen shows all-or-nothing |
| `TestE2ELifecycle` | real on-disk file, Close/Open, idempotent retry after restart, Page, Replay |
| R05 tests | inspect input/output regressions unchanged |

```sh

```

Windows: clone `ec032e2` (or later) and run the same `go test` selection; the E2E and all four crash injection points passed on Windows 11 amd64 with Go 1.26.5 on 2026-10-20 (real SQLite file, process exit, reopen).

## Acceptance mapping and gaps

Source-level coverage exists for W14-AC-002 (atomic commit and crash injection), AC-003 (idempotent retry/body mismatch), AC-007 (strict CAS), AC-010 (replay hash and no wall-clock dependence), and AC-015 (transaction-preserving pages and limits). AC-008 is covered only at the reservation primitive level; the Activity lifecycle is a test fixture and belongs to R10/R11.

Not covered: the adopted HTTP contract and canonical route/port (R07 has a provisional source foundation), CORE WorkSet/LifePolicy projections (R08/R09), production activity/space rules (R10/R11), PORTAL read projections, backup/restore operation, bounded catch-up/`recovery_gap`, UTF-8 transport-ID mapping, macOS behavior, and live/E2E acceptance through CORE. The acceptance matrix remains `not_run` until those scenarios are executed with owner evidence.
