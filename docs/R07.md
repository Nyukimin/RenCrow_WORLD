# R07: authenticated HTTP source foundation

Status: R07 source implementation of an explicit-config HTTP service around the R06 EventStore. Linux and Windows E2E (real binary, real SQLite file, auth, SSE, restart) are verified; macOS is unverified. The routes are the provisional R07 target table, not an adopted CORE/WORLD contract. There is no canonical WORLD production port in this repository, so this unit does not claim a deployed route.

## What is implemented

`internal/httpapi` provides:

- explicit listen address, Store path, scope, page bounds, SSE timing, and token digests;
- bearer authentication with constant-time digest comparison;
- least-privilege scopes: `read`, `write`, `stream`;
- optional token-to-scope binding (`world_id`, `timeline_id`, `timeline_epoch`);
- authenticated readiness and unauthenticated liveness;
- Snapshot, ordered Event pages, Receipt lookup, Command append, and SSE;
- strict body, page, and transaction limits from R06;
- CORE-owned `source_epoch/source_revision` are not accepted yet.

`cmd/rencrow-world serve --config PATH` starts the listener. The existing `inspect` command is unchanged and does not use this package.

## Configuration

```json
{
  "listen": "127.0.0.1:18793",
  "store_path": "/var/lib/rencrow/world.db",
  "scope": {
    "world_id": "rencrow-home",
    "timeline_id": "timeline-1",
    "timeline_epoch": "epoch-1"
  },
  "tokens": [
    {"id": "core-writer", "sha256": "<64 hex characters>", "scopes": ["read", "write", "stream"]}
  ],
  "page": {"max_events": 500, "max_bytes": 2097152},
  "sse": {"heartbeat_seconds": 15, "poll_millis": 200},
  "allow_probe_action": false
}
```

- The file is strict JSON; unknown fields and trailing values are rejected.
- `listen`, `store_path`, `scope`, and at least one token are mandatory. There is no default port.
- Non-loopback `listen` requires `"allow_remote": true`.
- Only SHA-256 digests are stored. Compute one with `printf '%s' "$TOKEN" | sha256sum`. The raw token is never read from or written to this file.
- A token may include `"scope": {"world_id": "...", "timeline_id": "...", "timeline_epoch": "..."}`. Requests using it for another configured scope return `scope_mismatch`.
- `initial_state` is optional. When present and the Timeline does not exist, `serve` creates it with the listed actors and resource capacities. It never overwrites an existing Timeline.
- `allow_probe_action` registers `debug.noop`, which appends one Event and changes no State. It exists for transport verification and is not an R10 world rule.
- Bounds: `page.max_events` 1..500, `page.max_bytes` 1024..2097152, `sse.heartbeat_seconds` 1..300, `sse.poll_millis` 20..5000.

## Provisional routes

| Route | Auth | Behavior |
|---|---|---|
| `GET /health/live` | none | process liveness only |
| `GET /health/ready` | any valid token | Store and Timeline readable; `503` when not ready |
| `GET /v1/worlds/{world}/timelines/{timeline}/snapshot` | `read` | Snapshot, `state_seq`, canonical `state_hash` |
| `GET /v1/worlds/{world}/timelines/{timeline}/events?after_seq=&limit=` | `read` | whole-transaction pages, `next_seq`, `done` |
| `GET /v1/worlds/{world}/timelines/{timeline}/receipts/{receipt}` | `read` | one Receipt |
| `POST /v1/worlds/{world}/timelines/{timeline}/commands` | `write` | append one Command; `Idempotency-Key` mandatory |
| `GET /v1/worlds/{world}/timelines/{timeline}/stream` | `stream` | SSE Snapshot/Event stream |

The configured scope is authoritative. `{world}` and `{timeline}` must match it exactly; otherwise the response is `403 scope_mismatch`. The epoch is not a path segment.

Command body:

```json
{"action": "debug.noop", "payload": {"hello": "world"}, "expected_state_seq": 3}
```

`expected_state_seq` is optional. Omitting it means no CAS. The authenticated token id becomes the Store `client_id`, so a client cannot spoof another owner. `recorded_at` is set by WORLD at commit time.

Status mapping:

| Status | Meaning |
|---|---|
| `200` | committed Receipt, or identical idempotent retry (`duplicate:true`) |
| `400` | malformed JSON, missing/invalid key or action, invalid page cursor/limit |
| `401` | missing or unknown bearer token |
| `403` | missing scope, scope mismatch, or non-loopback configuration refusal |
| `404` | unknown route or Receipt |
| `405` | wrong method |
| `409` | `idempotency_conflict`, `state_conflict`, or another rejected Receipt |
| `413` | body or transaction over the R06 bound |
| `415` | non-JSON command body |
| `422` | rejected `unknown_action` or `handler_error` |
| `503` | Timeline/Store not ready |

A rejected Command returns `409`/`422` with its Receipt, so the client can read `receipt.reason`. A same-key, same-body retry returns the original Receipt and adds no Event.

## SSE

- With no cursor, the first event is `snapshot` with a `state_seq` and `state_hash`; its SSE `id` is that boundary.
- With `Last-Event-ID` (or `after_seq`), the server resumes after that transaction boundary.
- A cursor ahead of the Store, or one inside a transaction, produces `resync` with a Snapshot instead of a partial transaction.
- Events are `world.event` with `id: <event_seq>` and the Event DTO as data. Whole transactions are always delivered together.
- `: keepalive` comments are sent at the configured heartbeat interval. `retry: 3000` is sent at connect.
- SSE uses the `Authorization` header. A browser `EventSource` cannot set that header, and browser clients must not hold WORLD credentials; CORE/PORTAL are the intended readers. No CORS or cookie path is provided.

## Security boundary

- Loopback bind by default; remote bind is an explicit opt-in.
- Only token digests are configured, compared in constant time, and never logged.
- No TLS, token issuance, rotation, revocation, rate limiting, or audit sink is implemented here. Terminate TLS and issue/rotate credentials in the owning runtime before any non-loopback deployment.
- The temporary `debug.noop` action is gated by configuration and must be disabled in production.
- Snapshot and Event reads are owner-scoped, not Viewer projections. Private-room redaction, before/after Viewer projection, and observation delivery remain R12/CORE work.

## Gaps

- The ASCII machine-ID versus Unicode-opaque ID conflict is still unresolved; this unit compares exact path values and does not define a transport mapping.
- No canonical port/route is adopted. The paths above are provisional and may change at the CORE/WORLD owner review.
- CORE projection (`source_epoch/source_revision`), LifePolicy, WorkSet, visits, confirmed utterances, Bundle validation/publish, and Timeline creation/fork routes are absent.
- No TLS, credential issuance/rotation, rate limiting, audit persistence, metrics, CORS, or browser EventSource path.
- No Viewer redaction or observation-candidate projection; `read` exposes the owner Snapshot for the configured scope.
- No macOS behavior evidence and no long-running/deployment acceptance.
- Acceptance matrix entries AC-016/AC-017 remain `not_run`; this document records source-level transport tests only.
