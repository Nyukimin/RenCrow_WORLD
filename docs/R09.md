# R09: WorkSet and LifePolicy meaning layer

Status: WORLD-side deterministic meaning layer plus a provisional read-only assessment route over validated R08 heads. It maps work-set/policy states without moving an Actor, selecting a concrete Activity, or changing WORLD State. The route is not an adopted CORE/WORLD contract and does not claim CORE adoption.

## Scope

`internal/projection` now exposes the validated `WorkSet`, `WorkItem`, and `LifePolicy` values and can re-parse a stored payload with `ParseWorkSet` / `ParseLifePolicy`. `internal/life.Assess` applies the meaning rules:

| Input | Meaning |
|---|---|
| no WorkSet head | `missing`; no success or completion inference |
| expired WorkSet | `expired`; no success, completion, or “no assigned work” inference |
| fresh empty WorkSet | `empty`; no current assigned work, but not success |
| fresh non-empty WorkSet | `assigned` |
| no LifePolicy head | `missing`; no new activity |
| fresh LifePolicy | current allowed non-cognitive activity IDs |
| expired LifePolicy | only `expired_fallback_activity_ids`, which must be a subset of the allowed IDs |
| unregistered activity ID | excluded; if nothing remains, new activity is blocked |

`internal/life.DefaultCatalog` registers the CORE-owned non-cognitive activity vocabulary (`change_clothes`, `exercise`, `idle`, `read`, `rest`, `sit`, `sleep`, `walk`). CORE owns the IDs; WORLD owns their concrete posture, motion, and occupancy mapping. The authenticated assessment route consumes this catalog and filters unregistered IDs from the response. The catalog is still not wired to an R10 controller.

The evaluation never extends expiry because a duplicate projection arrived. Only a newer CORE revision with a new `valid_until` can extend it.

## Provisional assessment route

```text
GET /v1/worlds/{world}/timelines/{timeline}/actors/{actor}/assessment
```

The route requires the `read` scope and an `actor` that is authorized in `core_projection_actors`. It reads the accepted WorkSet and LifePolicy heads for that Actor and returns a JSON assessment; it does not select or start an Activity, move an Actor, append an Event, or change WORLD State.

| Response field | Meaning |
|---|---|
| `work_set_state` | `missing`, `expired`, `empty`, or `assigned` |
| `policy_state` | `missing`, `expired`, or `fresh` |
| `work_presentation` | `kind`, `presence_task_ids`, `running_task_ids` |
| `permitted_activity_ids` | registered, sorted subset of the current policy |
| `new_activity_allowed` | whether a new non-cognitive Activity may be planned |
| `blocked_reason` | explicit reason when `new_activity_allowed` is false |
| `work_success` | always `false`; work success is not inferred from an empty Set |
| `assessed_at` | WORLD evaluation time in UTC |

A missing head is represented as `missing`, not as a success or a default permission. An unbound Actor is `403 actor_not_bound`; an unavailable timeline is `503 not_ready`; an unreadable stored head fails closed with `500 projection_unreadable`. The route is provisional and does not establish a canonical CORE/WORLD route.

## Work presentation mapping

`internal/life.WorkPresentation` is a planning input, not a movement command:

| WorkSet state | Presentation |
|---|---|
| queued only | `queued`; no work-presence movement |
| waiting/blocked only | `waiting` |
| running, no presence requirement | `remote`; no forced movement |
| running, presence required | `presence`; one controller may plan presence movement |
| mixed running items | `presence` dominates; otherwise `remote` |

A WORLD movement failure must not turn a CORE work result into failure. The actual movement, occupancy, and geometry remain R10/R11 work.

## Safe termination

`internal/life.PlanStop` requires an explicit interruption rule for an already-running Activity. It separates activity cancellation from physical occupancy release:

- no rule, non-interruptible, or missing ID → blocked;
- `CanInterrupt` → planned stop actions;
- occupancy is released only when the rule explicitly says so (for example, a seated Actor remains seated after the work activity is stopped).

These are WORLD events/decisions, not CORE work cancellation or completion.

## Continuation and candidate planning

`internal/life.plan.go` turns one `Assessment` into the three deterministic decisions that sit above it. It uses logical occupancy names only (`study_seat`, `path`); measured geometry, room graphs, and spatial readiness stay in R10/R11 (D-17/D-18), and nothing here appends an Event, changes State, or moves an Actor.

| Function | Decision | Boundary |
|---|---|---|
| `PlanContinuation` | keep (`continue`), stop through the activity's own interruption rule (`stop`), or stay in place when no safe stop exists (`hold`) | A fresh policy that dropped the ID is an explicit revocation; an expired policy keeps only its registered fallback subset. `hold` never grants a position change. |
| `PlanContinuation` occupancy | keeps `Stop.ReleaseOccupancy` refused while presence-required work runs (`presence_work_holds_occupancy`) | Activity cancellation and physical occupancy release stay separate operations |
| `PlanContinuation` presentation | clears the work presentation only for a fresh empty WorkSet | An expired WorkSet is unknown: it neither stops a permitted activity nor implies work success |
| `ExecutableActivityIDs` | the permitted IDs that also have a defined stop state, sorted, excluding activities that would move the Actor away while presence-required work runs | Publishes candidates only. Unknown work (expired WorkSet) never removes permitted non-cognitive options |
| `AdmitCandidate` | one requested activity → `admitted` or an explicit reason (`activity_not_permitted`, `no_activity_definition`, `presence_required`, or the Assessment's own blocked reason) | Selects nothing, starts nothing, and plans no movement; a later single life controller still owns every movement and occupancy decision |

## Gaps

- No R10 controller or HTTP route consumes `PlanContinuation`, `ExecutableActivityIDs`, or `AdmitCandidate`. The decisions are pure functions over an `Assessment`; nothing selects, starts, or stops a concrete Activity, and the assessment route is unchanged.
- No movement, room geometry, furniture occupancy, or measured spatial readiness.
- `RunningActivity.RequiresMovement` and `Occupancy` are caller-supplied logical names. Turning them into real movement and occupancy claims requires the D-17/D-18 geometry evidence that does not exist yet.
- The assessment route is provisional and has no adopted CORE consumer beyond the cross-repo read client tests.
- CORE WorkSet/LifePolicy adoption and real Outbox delivery remain pending.
- macOS behavior is unverified.
