# R09: WorkSet and LifePolicy meaning layer

Status: WORLD-side deterministic meaning layer. It consumes validated R08 projection heads and maps them to work-set/policy states without moving an Actor, selecting a concrete Activity, or changing WORLD State. It does not claim CORE adoption or a production route.

## Scope

`internal/projection` now exposes the validated `WorkSet`, `WorkItem`, and `LifePolicy` values and can re-parse a stored payload with `ParseWorkSet` / `ParseLifePolicy`. `internal/life.Assess` applies the meaning rules:

| Input | Meaning |
|---|---|
| no WorkSet head | `missing`; no success or completion inference |
| expired WorkSet | `expired`; no success, completion, or “no assigned work” inference |
| fresh empty WorkSet | `empty`; no current assigned work, but not success |
| fresh non-empty WorkSet | `assigned` |
| no LifePolicy head | `missing`; no new activity |
| fresh LifePolicy | current allowed non-cognitive activity IDs |
| expired LifePolicy | only `expired_fallback_activity_ids`, which must be a subset of the allowed IDs |
| unregistered activity ID | excluded; if nothing remains, new activity is blocked |

The evaluation never extends expiry because a duplicate projection arrived. Only a newer CORE revision with a new `valid_until` can extend it.

## Work presentation mapping

`internal/life.WorkPresentation` is a planning input, not a movement command:

| WorkSet state | Presentation |
|---|---|
| queued only | `queued`; no work-presence movement |
| waiting/blocked only | `waiting` |
| running, no presence requirement | `remote`; no forced movement |
| running, presence required | `presence`; one controller may plan presence movement |
| mixed running items | `presence` dominates; otherwise `remote` |

A WORLD movement failure must not turn a CORE work result into failure. The actual movement, occupancy, and geometry remain R10/R11 work.

## Safe termination

`internal/life.PlanStop` requires an explicit interruption rule for an already-running Activity. It separates activity cancellation from physical occupancy release:

- no rule, non-interruptible, or missing ID → blocked;
- `CanInterrupt` → planned stop actions;
- occupancy is released only when the rule explicitly says so (for example, a seated Actor remains seated after the work activity is stopped).

These are WORLD events/decisions, not CORE work cancellation or completion.

## Gaps

- No concrete Activity catalog, activity selection, or R10 controller is implemented.
- No movement, room geometry, furniture occupancy, or measured spatial readiness.
- No HTTP route exposes the assessment; the meaning layer is consumed by later R10 code.
- CORE WorkSet/LifePolicy adoption and real Outbox delivery remain pending.
- macOS behavior is unverified.
